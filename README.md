# HackFlow · Code Invaders

HackFlow — площадка для студенческих хакатонов и чемпионатов по спортивному программированию. Организатор ведёт несколько мероприятий из одного кабинета. Команда в одном месте находит условия отбора, задания, расписание, материалы, обратную связь и статус сдачи.

Проект создан командой **Code Invaders** для кейса «Актион — HackFlow». Основной сценарий охватывает путь от формирования команды и подачи заявки до работы над заданием и передачи результата организатору.

## Как работает площадка

1. Организатор создаёт мероприятие, выбирает формат, задаёт сроки, размер состава и условия отбора. Опубликованная карточка доступна в каталоге.
2. Участники собирают команду заранее через код приглашения. Капитан подаёт одну заявку за весь состав. Если организатор разрешил индивидуальное участие, заявку можно подать одному.
3. Организатор рассматривает заявку. После одобрения команда получает доступ к рабочему пространству. Состав сохраняется в том виде, в котором его отправили, поэтому изменения команды на площадке влияют на следующие заявки.
4. На хакатоне команда ведёт задачи на доске, общается в чате и при необходимости запрашивает чекпоинт. Капитан отправляет итоговое решение, организатор видит его в кабинете, а назначенный эксперт может оставить заключение.

| Роль | Возможности |
| --- | --- |
| Участник | Вступает в команду, читает программу и материалы, общается в чате, обновляет свои задачи и получает уведомления. |
| Капитан | Подаёт заявку и сдаёт проект за команду, назначает ответственных, меняет статусы задач, оставляет замечания и запрашивает чекпоинт. |
| Организатор | Настраивает и публикует мероприятия, рассматривает заявки, назначает менторов и экспертов, добавляет задания и материалы, назначает звонки и следит за прогрессом. |
| Ментор | Видит назначенные команды и помогает им через диалог с капитаном. |
| Эксперт | Видит назначенные команды, открывает сданные решения и публикует заключение по критериям мероприятия. |

## Форматы мероприятий

- **Хакатон.** В «Настройках мероприятия» опубликуйте условия отбора. Команды увидят их до отправки заявки. В разделе «Кейсы» добавьте один или несколько кейсов. Если кейсов несколько, капитан указывает выбранный в заявке.
- **Чемпионат по спортивному программированию.** Выберите этот формат при создании мероприятия, задайте размер состава и правила зачёта. В «Задачах» опубликуйте условия, в расписании добавьте раунды. Ссылки на проверку решений и таблицу результатов можно указать в настройках. Задачи и файлы откроются допущенным участникам в момент старта. Проверка решений проходит во внешней системе.

Файлы добавляются внутри карточки конкретного кейса или задачи. Лимит — 2 МБ на файл и 8 МБ на мероприятие. В обычном режиме вложения сохраняются вместе с данными приложения. Для открытого демо они действуют до перезапуска.

## Вход, регистрация и демо на Render

- На главной странице можно войти или создать аккаунт с почтой и паролем. Для регистрации организатора задайте в настройках сервиса `HACKFLOW_ORGANIZER_CODE` длиной от 16 символов и передайте код организаторам. Менторы и эксперты регистрируются по приглашениям от организатора.
- Кнопка «Попробовать демо» открывает `/review`. С настройкой `HACKFLOW_PUBLIC_DEMO=1` там можно выбрать роль без кода. Этот режим включён и в Dockerfile, и в `render.yaml`.
- Демо хранит изменения в памяти. Обычные аккаунты и мероприятия пишутся в `mvp.json`. Чтобы они сохранялись после перезапуска Render, подключите постоянный диск и задайте `HACKFLOW_DATA_DIR` равным пути его подключения. В `render.yaml` уже настроен диск на `/var/data`. На бесплатном веб-сервисе Render локальные файлы сбрасываются при перезапуске.

## Техническое устройство

### Стек и структура проекта

Приложение работает на **Node.js 24 LTS** без внешних npm-зависимостей. HTTP-сервер использует стандартный модуль `node:http` и формирует HTML на сервере. Обычные действия работают через формы, а клиентский JavaScript добавляет перетаскивание задач, поиск, фильтры, выбор темы и обновление информации о чекпоинте.

| Файл | Назначение |
| --- | --- |
| [server.mjs](server.mjs) | HTTP-маршруты, HTML-страницы, авторизация, правила работы с мероприятиями, заявки и запись данных. |
| [board.js](board.js) | Доска и список задач, фильтры, выбор темы и обновление данных о чекпоинте. |
| [style.css](style.css) | Адаптивные макеты, светлая и тёмная темы. |
| [package.json](package.json) | Команды запуска, локального демо и проверки синтаксиса. |
| [Dockerfile](Dockerfile) | Контейнер для открытого демо, включая выбор роли без кода. |
| [render.yaml](render.yaml) | Blueprint для сервиса Node.js с постоянным диском на Render. |
| [REVIEW.md](REVIEW.md) | Инструкция для жюри и сценарий демонстрации. |

### Запросы и данные

- Аккаунт и команда на площадке общие для всех мероприятий. Допуск, заявки, составы на конкретном мероприятии, задания, расписание, чат и сдача привязаны к выбранному мероприятию. Сервер определяет мероприятие по параметру `hack` и использует отдельный контекст для каждого запроса.
- Отправка формы проходит проверку на сервере. После успешного действия сервер сохраняет изменения и перенаправляет пользователя на нужную страницу. Браузер проверяет обновление чекпоинта раз в 8 секунд и меняет соответствующий блок страницы.
- В обычном режиме данные пишутся в `mvp.json` через временный файл и замену предыдущего файла. Папка по умолчанию — `data/`. Для Render используется `HACKFLOW_DATA_DIR`, например `/var/data`. Вложения хранятся вместе с данными в Base64. Такая схема рассчитана на один экземпляр сервера.
- Открытое демо использует отдельный набор тестовых данных в памяти. Действия в демо не меняют файл обычной площадки. Сессии привязаны к своему режиму и хранятся в памяти процесса. После перезапуска нужно войти заново.

### Доступ и интеграции

- Пароли хранятся как хеши `scrypt` с индивидуальной солью. В публичном режиме минимальная длина нового пароля — 12 символов. Идентификатор сессии передаётся в cookie с `HttpOnly` и `SameSite=Strict`. В публичном режиме добавляется `Secure`. Сервер ограничивает частоту попыток входа.
- Сервер проверяет права при каждом защищённом действии. Организатор управляет своими мероприятиями, член команды работает со своим составом, а ментор и эксперт получают доступ к назначенным командам. При скачивании вложения проверяются права на мероприятие. Для чемпионата учитывается время старта.
- Чекпоинты открывают ссылку на внешний видеосервис. В спортивном программировании проверка решений и таблица результатов находятся во внешней системе. В текущем MVP к ней ведут ссылки из кабинета, обмен вердиктами через API запланирован. Подтверждение почты и восстановление пароля пока не подключены.



1. **Регистрация.** Команда видит условия отбора, капитан выбирает кейс, организатор одобряет заявку, после чего участник может открыть файл кейса.
2. **Работа команды.** Капитан меняет статус задачи и оставляет замечание. Ответственный видит уведомление и открывает нужную карточку. Капитан запрашивает чекпоинт, организатор назначает время, команда видит обновление.
3. **Финиш мероприятия.** На хакатоне капитан сдаёт решение, а эксперт оставляет заключение. В чемпионате задачи открываются в момент старта, и участник переходит во внешнюю систему проверки.
