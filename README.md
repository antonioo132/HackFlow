# HackFlow · Code Invaders

Площадка для студенческих хакатонов и чемпионатов по спортивному программированию. Участники могут собрать команду заранее и подать заявку через капитана. Если организатор разрешил индивидуальное участие, заявку можно отправить одному. После подтверждения открывается рабочее пространство с программой и заданиями.

## Форматы мероприятий

- **Хакатон.** В «Настройках мероприятия» опубликуйте условия отбора. Команды увидят их до отправки заявки. В разделе «Кейсы» добавьте один или несколько кейсов. Если кейсов несколько, капитан указывает выбранный в заявке.
- **Чемпионат по спортивному программированию.** Выберите этот формат при создании мероприятия, задайте размер состава и правила зачёта. В «Задачах» опубликуйте условия, в расписании добавьте раунды. Ссылки на проверку решений и таблицу результатов можно указать в настройках. Задачи и файлы откроются допущенным участникам в момент старта. Проверка решений проходит во внешней системе.

Файлы добавляются внутри карточки конкретного кейса или задачи. Лимит — 2 МБ на файл и 8 МБ на мероприятие. В обычном режиме вложения сохраняются вместе с данными приложения. Для открытого демо они действуют до перезапуска.

## Запуск на компьютере

Нужен Node.js 24 LTS. Внешних npm-зависимостей нет.

```powershell
npm run demo
```

Откройте адрес из терминала и выберите роль. Изменения в локальном демо сбрасываются при перезапуске. Для режима с постоянными аккаунтами запустите `npm start`. Первый локальный организатор может зарегистрироваться без кода.

## Загрузка на GitHub

Создайте пустой репозиторий на GitHub. Выполните команды **внутри папки с этим README**, заменив URL адресом своего репозитория.

```powershell
git init -b main
git add .
git commit -m "Add HackFlow MVP"
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```

Перед коммитом `git status --short` должен показывать только файлы проекта. `data/`, `.env` и журналы игнорируются. Код для жюри и код приглашения организатора передавайте отдельно от репозитория.

## Развёртывание на Render

### Docker Web Service, открытое демо для жюри

Выберите **New → Web Service**, подключите репозиторий и оставьте **Docker**, ветку `main` и пустое поле Root Directory. После деплоя откройте `/review`. Достаточно выбрать роль и нажать «Войти в демо». Изменения хранятся в памяти и сбрасываются при перезапуске. Приложение в этом режиме работает только с демонстрационными данными.

Dockerfile включает режим `HACKFLOW_PUBLIC_DEMO=1` по умолчанию. Чтобы использовать этот контейнер как обычную площадку с аккаунтами, укажите `HACKFLOW_PUBLIC_DEMO=0` в настройках сервиса и подключите постоянный диск. Ключ `HACKFLOW_REVIEW_KEY` нужен только для демо с кодом в обычном режиме.

### Blueprint, площадка с постоянным хранилищем

1. В Render выберите **New → Blueprint** и подключите репозиторий GitHub. Файл `render.yaml` лежит в его корне.
2. Проверьте настройки перед подтверждением: Node.js, сборка `npm run check`, запуск `npm start`, проверка `/health`. Blueprint создаёт сервис **Starter с платным постоянным диском 1 ГБ** по пути `/var/data`.
3. После развёртывания откройте `https://<имя-сервиса>.onrender.com/health`. Ожидаемый ответ — `ok`.
4. В **Environment** возьмите сгенерированный `HACKFLOW_REVIEW_KEY`. Откройте `/review`, выберите тестовую роль и введите этот код. Жюри передайте ссылку на `/review` и только этот код.
5. `HACKFLOW_ORGANIZER_CODE` используется для регистрации отдельных аккаунтов организаторов. Передавайте его только людям, которым нужен этот доступ.

Blueprint создаёт демоданные при первом запуске на пустом диске. Чтобы начать с чистой площадки без тестовых аккаунтов, при ручном создании сервиса не задавайте `HACKFLOW_REVIEW_KEY`. Если вы уже запустили сервис без демо и начали добавлять данные, включение кода позже не заменит существующие аккаунты и мероприятия.

### Настройки для ручного создания Web Service

| Поле | Значение |
| --- | --- |
| Runtime | Node |
| Build Command | `npm run check` |
| Start Command | `npm start` |
| Health Check Path | `/health` |
| `HOST` | `0.0.0.0` |
| `HACKFLOW_MODE` | `review` |
| `HACKFLOW_DATA_DIR` | `/var/data`, если подключён постоянный диск |
| `HACKFLOW_REVIEW_KEY` | Случайное значение от 16 символов, если нужен вход для жюри |
| `HACKFLOW_ORGANIZER_CODE` | Отдельное случайное значение от 16 символов |

Render сам назначает `PORT`. Без постоянного диска данные на бесплатном сервисе могут теряться после перезапуска или нового деплоя. Для сдачи, где нужно сохранить заявки и результаты, подключите диск. См. [документацию Render о дисках](https://render.com/docs/disks).

В папке есть Dockerfile для запуска в контейнере. Blueprint использует нативный Node.js.

## Как устроено

Node.js обрабатывает запросы и формирует HTML. Интерфейс написан на CSS и JavaScript. Пароли хранятся как хеши scrypt с солью. В публичном режиме новые пароли должны содержать минимум 12 символов. Данные хранятся в `mvp.json` в указанной папке, сессии — в памяти процесса. После перезапуска потребуется снова войти. Для файлового хранилища используется один экземпляр приложения. Звонки проходят по внешним ссылкам, письма и восстановление пароля не подключены.
